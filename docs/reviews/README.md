# reviews — what we showed people, and when

> Dated. Each file here is a point-in-time account of the project given to an audience. None of it is current truth — it is the record of what was said on a date, and the prompt that produced it.

A review is not a spec. When a review and a version directory disagree, the version directory wins and the review is simply older. Nothing else in `docs/` should link *into* a review to justify a claim.

Each file carries the prompt, not just the output. The deck is disposable; the prompt is the thing worth keeping, because the next review is the last one with the content swapped.
